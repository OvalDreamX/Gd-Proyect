# 0.2.5F7B — Unified Actuator Allocation

## Changes

- Replaced separate main-vector and maneuver allocator passes with one combined six-dimensional wrench allocation.
- Enforced one bounded scalar output per physical vane per physics tick.
- Applied each actuator's achieved force once at its actual anchor position.
- Combined main-vector hull-datum torque with pilot pitch/roll/yaw torque in the same target wrench.
- Preserved the F7A main-vector direction convention, TWR cross-fade and endpoint ratings.
- Reserved pitch/roll authority from propulsion demand when those axes are commanded, rather than double-spending actuator capacity.
- Preserved bounded damage redistribution and low-main-power maneuver boost inside the unified force limit.
- Replaced group-based thermal load estimates with loads derived from measured per-vane force contributions.
- Replaced group-based lift telemetry/capacity lookup with `lift` control-weight and actuator-axis metadata.
- Preserved legacy HUD/test telemetry keys as compatibility aliases.

## Engineering decisions

The solver's target wrench is the sum of (1) the main propulsion resultant acting through the hull datum and (2) requested maneuver torque. The solver works about the current COM, so the main datum moment is explicitly included. Forces are then applied at physical actuator anchors exactly once. This is equivalent at the rigid-body wrench level while respecting each actuator's single scalar output bound.

When pitch or roll is commanded, a corresponding reserve is removed from the propulsion target. This is deliberate: the old two-pass implementation could exceed the physical actuator limit by spending the same vane output twice. The new system does not silently preserve that impossible behavior.
