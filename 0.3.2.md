# Space Trucker — Patch 0.3.2 (Phase 3B: Environment Data & Local Physical References)

**Milestone:** Phase 3B — Environment data and local physical references  
**Target engine:** Godot 4.7.2 Stable · GDScript · GL Compatibility  
**Status:** Ready for Godot 4.7.2 headless & runtime verification

---

## Why this patch exists
Per `docs/GDD_ANNEX_v0_3.md` §4.1, §4.2, and §9 (Phase 3B), the ship must be able to receive planetary or local-space environment conditions (gravity, local up/north/east, atmospheric density, wind, and ambient temperature) through a clean data interface without breaking `scenes/test_range.tscn` or duplicating ship controllers.

## What was added
- `0.3.2.md` — Root milestone changelog and verification guide.
- `scripts/celestial_body_definition.gd` (`CelestialBodyDefinition`) — Data resource defining body ID, radius, surface gravity, gravitational parameter `mu`, rotation period, north axis, atmosphere parameters, and pure gravity/density helpers.
- `scripts/environment_profile.gd` (`EnvironmentProfile`) — Data resource defining `PLANET_SURFACE` vs `LOCAL_SPACE` profiles, gravity, atmosphere, wind, thermal ambient temperature, and sky/ambient lighting parameters.
- `scripts/environment_manager.gd` (`EnvironmentManager`) — Scene-level runtime provider that binds an active `EnvironmentProfile`, keeps an optional `PlanetaryReferenceFrame` synchronized, emits `environment_profile_changed`, and serves deterministic local-frame, gravity, atmosphere, and telemetry queries.
- `data/celestial/test_planet.tres` — Compact Phase 3 test planet definition (`&"test_planet"`, radius `60,000 m`, surface gravity `9.81 m/s²`, atmosphere top `45,000 m`).
- `data/environments/test_planet_surface.tres` — Planetary surface `EnvironmentProfile` (`&"env_test_planet_surface"`) linked to `test_planet.tres`.
- `data/environments/station_local_space.tres` — Local-space `EnvironmentProfile` (`&"env_station_local_space"`) enforcing zero gravity, zero air density, zero wind, and `-150.0°C` ambient temperature.
- `tests/environment_profile_test.gd` — Pure logic tests for `CelestialBodyDefinition` and `EnvironmentProfile`.
- `tests/environment_manager_test.gd` — Integration tests verifying the same ship behaves under both `test_planet_surface.tres` and `station_local_space.tres` (zero-g, zero drag/wind, valid sensor snapshots) and confirming `test_range.tscn` remains untouched.

## What was updated (backward-compatible hooks)
- `scripts/planetary_reference_frame.gd` — Added `apply_environment_profile(profile)` so a scene's `PlanetaryReferenceFrame` can be configured directly from an `EnvironmentProfile` resource. All existing defaults remain unchanged.
- `scripts/planetary_gravity_body.gd` — Added optional `EnvironmentManager` lookup so `LOCAL_SPACE` scenes explicitly disable Godot's built-in 9.8 m/s² world gravity (`gravity_scale = 0.0`, zero central gravity force) instead of falling back to default downward gravity.
- `scripts/atmospheric_flight_model.gd` — Added optional `EnvironmentManager` binding and optional `atmosphere_top_altitude_m` cutoff (default `0.0` = disabled to preserve existing 3-arg `calculate_air_density()` callers). When no `EnvironmentManager` is present (such as `test_range.tscn`), all Phase 2 defaults remain 100% active.
- `scripts/flight_sensor_suite.gd` — Added optional `EnvironmentManager` lookup for `LOCAL_SPACE` frames and added `instrument_environment_id`, `instrument_environment_type`, and `instrument_ambient_temperature_celsius` to the instrument snapshot.
