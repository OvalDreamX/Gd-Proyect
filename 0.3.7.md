# Space Trucker — Patch 0.3.7 (Phase 3G-Pre: Authoritative Ship JSON, Freighter Rebalance, Convective Radiators & Tiered Integrity)

**Milestone:** Authoritative `ship.json` wiring, YT-1300-class freighter flight/climb balance, convective + radiative cooling, tiered 75%/50%/25% vane wear & failures, and updated documentation  
**Target engine:** Godot 4.7.2 Stable · GDScript · GL Compatibility  
**Builds on:** Patch `0.3.6` (preserves `EnvironmentManager`, `PlanetSurface`, `StationLocalSpace`, `SimulationClock`, `TransitionCoordinator`, and `J` hyperspace loop)

---

## Why changes to `ship.json` previously had no effect
`ShipDefinitionLoader` was previously only wired into `RepulsorliftGroundEffectSystem` (for ground-effect probe configuration). All other subsystems still read hardcoded `@export` defaults on `scenes/ship.tscn`.  
Patch `0.3.7` connects **`ShipInteractable`** directly to `ShipDefinitionLoader` so **every ship subsystem hydrates live from `res://data/ships/prototype_freighter/ship.json`** at startup (while preserving scene defaults for standalone Phase 2 unit tests and preserving all Blender/GLB anchor names).

## What was added & updated

### Live `ship.json` Wiring (Archetype-Ready for Freighter, Fighter & Heavy Barge)
- `scripts/ship_definition.gd` & `scripts/ship_definition_loader.gd` — Added optional `thermal_and_integrity` block and lightweight validation for expanded `propulsion`, `handling`, `aerodynamics`, `cameras`, and `thermal_and_integrity` sections without breaking existing v1 JSON mods.
- `scripts/ship_interactable.gd` — Loads `ship_definition_path` (`res://data/ships/prototype_freighter/ship.json`) in `_enter_tree()`, sets authoritative `mass` / `max_payload_mass_kg`, and hydrates all ship subsystems cleanly on `_ready()` (plus `set_ship_definition()` / `load_ship_definition_file()` for runtime swapping).
- `scripts/cargo_system.gd` — Reads dry mass, max payload, hull dimensions, cargo hold min/max bounds, distribution dimensions, and presets from `ShipDefinition`, and computes hover throttle dynamically from bottom collective TWR.
- `scripts/repulsorlift_system.gd`, `scripts/ship_flight_controller.gd`, `scripts/atmospheric_flight_model.gd`, `scripts/flight_control_computer.gd`, `scripts/ship_camera_controller.gd` — Each subsystem now hydrates its parameters from `ShipDefinition`.

### YT-1300 Freighter Rebalance & Altitude Radiator Sweet Spot (F-104 Envelope)
- `data/ships/prototype_freighter/ship.json` — Tuned for an authentic heavy-ish medium freighter:
  - Keeps `30,000 kg` dry / `25,000 kg` payload (`55,000 kg` max gross), `1.10` bottom lift TWR, and `1.50` rear propulsion TWR (so heavy cargo noticeably affects climb and hover throttle).
  - Lowered `drag_coefficient` (`0.80 -> 0.34`), expanded `shield_effective_lift_area_m2` (`36 -> 52 m²`), raised `shield_max_lift_coefficient` (`1.10 -> 1.35`) with gentle induced drag (`0.05`), and crispened control/power response so thinning upper air translates smoothly into rising true airspeed and clean `45+ km` zoom climbs.
- `scripts/celestial_body_definition.gd`, `scripts/environment_profile.gd`, `scripts/environment_manager.gd`, `data/celestial/test_planet.tres` — Added altitude temperature curve (`+16°C` Starport SL -> `-58°C` cold tropopause band at `14 km` -> `-135°C` at `45+ km`), creating an organic mid-altitude radiator & acceleration sweet spot.

### Dual-Mode Convective Radiators & Tiered Integrity (`75% / 50% / 25%`)
- `scripts/vane_controller.gd` — Added:
  - **Convective Air + Vacuum Radiation Cooling:** `effective_cooling = vacuum_cooling + air_cooling * (rho / 1.225)^0.65 * (1 + gain * speed / ref) + high_temp_radiation_bonus`. Dense, fast cold air sheds heat much faster than vacuum, while critical thrust settles into a controlled plateau instead of instantly spiking to `+490°C`.
  - **Realistic Endurance Curve:** Calibrated for **60+ minutes** in normal green-zone cruise and **8–10 minutes** of continuous full-power critical sustain before sliding below `75%` integrity.
  - **Tiered Integrity & Failure Model (`100% -> 75% -> 50% -> 25% -> 0%`):**
    - `100%..75%`: Nominal response, zero random faults.
    - `75%..50%`: Every `%` below `75%` linearly adds sputter probability/strength, vector misalignment drift, and control response lag while capping baseline authority loss mild (~15–25% degraded feel—never an unflyable vane early on).
    - `50%..25%`: Wear rate and fault severity ramp exponentially; noticeable **TWR droop** begins.
    - `<25%`: Heavy TWR degradation plus **field startup misfires** (`FIELD STARTUP MISFIRE — RETRY (F)` in HUD/F3).
