# Space Trucker — Phase 2D: Collective Repulsorlift

## Install

1. Extract this ZIP into the existing Godot project root.
2. Preserve the included folder structure.
3. Overwrite the existing files when prompted.
4. Open the project in Godot 4.7.2 Stable and run the existing `test_range.tscn` main scene.

Files included:

- `scripts/repulsorlift_system.gd` — new collective-lift force component.
- `scripts/ship_flight_controller.gd` — updated to feed actual field output into the lift component.
- `scripts/flight_hud.gd` — updated force/TWR telemetry.
- `scenes/ship.tscn` — adds the RepulsorliftSystem child node.

## What this milestone does

The field's **actual power output**, not its setpoint, produces a single central force opposite the ship's effective gravity vector. The force is applied once per physics tick using `RigidBody3D.apply_central_force()`.

The prototype uses a maximum lift TWR of 1.1 as an Inspector-exposed PLACEHOLDER from GDD Section 9.6. At full output, that is 10% more lift than the ship's weight. The theoretical hover threshold is therefore about 90.9% actual field output. These are test values, not approved balance values.

Q/E continues to move the vector-distribution command and actual readout, but does not change the force direction in this milestone. The collective-lift test is deliberately fixed vertically, following GDD Prototype Step 2. Directional vectoring is deferred to the later vectoring milestone. Yaw, pitch and roll remain telemetry-only.

No vane groups, torque, FCC, aerodynamics, thermal simulation or damage behavior are added.

## Test sequence

1. Start the scene and allow the ship to settle on the pad.
2. Confirm the ship remains on the pad with the field OFF.
3. Enter the cockpit and activate the field with F.
4. Wait for OFF → STARTING → ONLINE and release the controls as required by the neutral-input interlock.
5. Hold W to increase the power setpoint. Confirm the output rises more slowly than the setpoint.
6. Watch `COLLECTIVE FORCE`, `LIFT TWR` and vertical speed on the HUD.
7. At output below 1.0 TWR, the ship should remain unable to hover; at 1.0 TWR it should approximately balance gravity; above 1.0 TWR it should rise.
8. At the default maximum TWR of 1.1, full output should produce a modest upward acceleration, not an arcade-like launch.
9. Reduce power with S. As actual output drops below the hover threshold, the ship should descend.
10. Press F to shut the field off. Lift force should return to zero while gravity continues acting normally.
11. Confirm Q/E still changes its telemetry values but does not steer the lift vector in this milestone.
12. Confirm C, RMB, Shift, F3, and external camera zoom still work.

## Expected default numbers

At 12,000 kg and standard gravity of approximately 9.8 m/s²:

- Weight: approximately 117,600 N.
- Maximum collective lift at 1.1 TWR: approximately 129,360 N.
- Hover threshold: approximately 90.9% actual power output.
- Net upward acceleration at 100% output: approximately 0.98 m/s² (0.1 g).

Numbers vary slightly with the effective gravity returned by Godot and the configured ship mass.

## Known scope limits

- Lift always acts opposite gravity and is applied at the center of mass.
- No rotation is generated by collective lift.
- Q/E does not yet rotate the force direction.
- The 1.1 TWR value is explicitly provisional.
- The implementation has not been runtime-tested in this environment. Verify in Godot 4.7.2 before treating Phase 2D as validated.
